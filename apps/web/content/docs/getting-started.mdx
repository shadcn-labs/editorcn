## Prerequisites

- React 18 or 19
- A shadcn/ui setup with Tailwind CSS v4
- Tiptap v3 (`@tiptap/react` 3.x)

## Choose your editor

editorcn offers two editor packages. Pick the one that fits your use case:

- **[@editorcn/editor](#option-1-editorcneditor-toolbar-style)** — a classic toolbar-style rich text editor
- **[@editorcn/block-editor](#option-2-editorcnblock-editor-blocks-style)** — a Notion-style block editor with slash commands

For rendering saved content read-only (blog posts, previews, chat history), see the [Static Renderer](./static-renderer).

Both packages can be installed either via **npm** or via the **shadcn registry**:

- **shadcn registry** (recommended) copies the component source directly into your project (under `components/`), so you own and can customize the code. This is the preferred method since it gives you full control over styling and behavior.
- **npm** installs the package as a regular dependency from the npm registry. Use this if you'd rather not vendor the component source into your repo.

## Setup

Since the shadcn registry is the recommended install method, add the editorcn registry to your `components.json` first (skip this if you're installing via npm only):

```json
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "registries": {
    "@editorcn": "https://www.rtecn.space/r/styles/{style}/{name}.json"
  }
}
```

<Callout title="Check your iconLibrary">
  The icons are written for the `iconLibrary` in your `components.json`, which
  must be `lucide`, `tabler`, `hugeicons`, `phosphor` or `remixicon`. Older
  projects with `"iconLibrary": "radix"` get a build error about
  `./icon-placeholder`. Change it to `"lucide"` before installing, and install
  `lucide-react` if your project doesn't have it (the CLI doesn't install icon
  packages). See [Icon library](/docs/editor#icon-library).
</Callout>

### Option 1: @editorcn/editor (Toolbar-style)

**Install via the shadcn registry (recommended):**

```bash
npx shadcn@latest add @editorcn/editor
```

This also installs every Tiptap extension the toolbar controls use (text align, placeholder, character count, color and highlight), so the example below works without installing anything else.

**Or install via npm:**

```bash
npm install @editorcn/editor @tiptap/react @tiptap/pm @tiptap/starter-kit @tiptap/extension-link @tiptap/extension-text-align @tiptap/extension-placeholder @tiptap/extension-character-count @tiptap/extension-text-style @tiptap/extension-color @tiptap/extension-highlight
```

Import the styles:

```tsx
// Your shadcn globals
import "@/app/globals.css";

// Editor component styles
import "@/components/editor/style.css";
```

> **Order matters**: Import your shadcn globals first, then the editor styles.

If you installed via npm, import `@editorcn/editor/style.css` instead. In the CSS file that imports `tailwindcss`, also import the editor's theme and add the package to Tailwind's sources (the path is relative to that file):

```css
@import "@editorcn/editor/theme.css";
@source "../node_modules/@editorcn/editor/dist";
```

The toolbar, menus and other chrome are styled with Tailwind classes, and Tailwind doesn't scan `node_modules` by default. The theme defines the menu and toolbar animations. The shadcn registry doesn't need either, because the source is in your project and the CLI adds the animations to your CSS.

```tsx
"use client";

import { useEditor } from "@tiptap/react";
import { StarterKit } from "@tiptap/starter-kit";
import { TextAlign } from "@tiptap/extension-text-align";
import { Placeholder } from "@tiptap/extension-placeholder";
import { TextStyle } from "@tiptap/extension-text-style";
import { Color } from "@tiptap/extension-color";
import { Highlight } from "@tiptap/extension-highlight";
import { CharacterCount } from "@tiptap/extension-character-count";
import { RichTextEditor, Link } from "@/components/editor";
import "@/components/editor/style.css";

export function MyEditor() {
  const editor = useEditor({
    immediatelyRender: false,
    shouldRerenderOnTransaction: false,
    extensions: [
      StarterKit.configure({
        heading: { levels: [1, 2, 3, 4, 5, 6] },
        link: false,
      }),
      Link,
      TextAlign.configure({ types: ["heading", "paragraph"] }),
      Placeholder.configure({ placeholder: "Start typing..." }),
      CharacterCount,
      TextStyle,
      Color,
      Highlight.configure({ multicolor: true }),
    ],
  });

  return (
    <RichTextEditor editor={editor}>
      <RichTextEditor.Toolbar sticky>
        <RichTextEditor.ControlsGroup>
          <RichTextEditor.Bold />
          <RichTextEditor.Italic />
          <RichTextEditor.Underline />
          <RichTextEditor.Strikethrough />
          <RichTextEditor.Code />
          <RichTextEditor.ClearFormatting />
        </RichTextEditor.ControlsGroup>

        <RichTextEditor.ControlsGroup>
          <RichTextEditor.H1 />
          <RichTextEditor.H2 />
          <RichTextEditor.H3 />
        </RichTextEditor.ControlsGroup>

        <RichTextEditor.ControlsGroup>
          <RichTextEditor.BulletList />
          <RichTextEditor.OrderedList />
          <RichTextEditor.Blockquote />
          <RichTextEditor.Hr />
        </RichTextEditor.ControlsGroup>

        <RichTextEditor.ControlsGroup>
          <RichTextEditor.AlignLeft />
          <RichTextEditor.AlignCenter />
          <RichTextEditor.AlignRight />
        </RichTextEditor.ControlsGroup>

        <RichTextEditor.ControlsGroup>
          <RichTextEditor.Link />
          <RichTextEditor.Unlink />
        </RichTextEditor.ControlsGroup>

        <RichTextEditor.ControlsGroup>
          <RichTextEditor.Undo />
          <RichTextEditor.Redo />
        </RichTextEditor.ControlsGroup>
      </RichTextEditor.Toolbar>

      <RichTextEditor.BubbleMenu editor={editor} />

      <RichTextEditor.Content />
      <RichTextEditor.Footer showWordCount />
    </RichTextEditor>
  );
}
```

`StarterKit` v3 already includes `Link` and `Underline`. Pass `link: false` so it doesn't register a second link extension next to editorcn's `Link`, and don't add `@tiptap/extension-underline` yourself. Otherwise Tiptap warns about duplicate extension names.

### Option 2: @editorcn/block-editor (Blocks-style)

**Install via the shadcn registry (recommended):**

```bash
npx shadcn@latest add @editorcn/block-editor @editorcn/table @editorcn/image-placeholder
```

This installs the block editor with the Tiptap extensions it uses (placeholder, task lists, text align, color and highlight), plus the editorcn [Table](/docs/extensions/table) and [Image Placeholder](/docs/extensions/image-placeholder) extensions used in the example below.

**Or install via npm:**

```bash
npm install @editorcn/block-editor @editorcn/extensions @tiptap/react @tiptap/pm @tiptap/starter-kit @tiptap/suggestion @tiptap/extension-drag-handle-react @tiptap/extension-placeholder @tiptap/extension-task-list @tiptap/extension-task-item @tiptap/extension-text-align @tiptap/extension-text-style @tiptap/extension-color @tiptap/extension-highlight
```

With npm, import the extensions from `@editorcn/extensions/table` and `@editorcn/extensions/image-placeholder` instead of `@/components/extensions/...`.

Import the styles:

```tsx
import "@/components/block-editor/style.css";
```

If you installed via npm, import `@editorcn/block-editor/style.css` instead. In the CSS file that imports `tailwindcss`, also import the block editor's theme and add the package to Tailwind's sources (the path is relative to that file):

```css
@import "@editorcn/block-editor/theme.css";
@source "../node_modules/@editorcn/block-editor/dist";
```

The toolbar, menus and other chrome are styled with Tailwind classes, and Tailwind doesn't scan `node_modules` by default. The theme defines the menu animations. The shadcn registry doesn't need either, because the source is in your project and the CLI adds the animations to your CSS.

```tsx
"use client";

import { useEditor } from "@tiptap/react";
import { StarterKit } from "@tiptap/starter-kit";
import { Placeholder } from "@tiptap/extension-placeholder";
import { TaskList } from "@tiptap/extension-task-list";
import { TaskItem } from "@tiptap/extension-task-item";
import { TextAlign } from "@tiptap/extension-text-align";
import { TextStyle } from "@tiptap/extension-text-style";
import { Color } from "@tiptap/extension-color";
import { Highlight } from "@tiptap/extension-highlight";
import {
  BlockEditor,
  SlashCommand,
  getSlashCommandSuggestion,
} from "@/components/block-editor";
import {
  ImagePlaceholder,
  ResizableImage,
  imagePlaceholderSlashCommandItem,
} from "@/components/extensions/image-placeholder";
import { Table, tableSlashCommandItem } from "@/components/extensions/table";
import { TableHoverOverlay } from "@/components/extensions/table/table-hover-overlay";
import "@/components/block-editor/style.css";
import "@/components/extensions/image-placeholder/style.css";
import "@/components/extensions/table/style.css";

export function MyEditor() {
  const editor = useEditor({
    immediatelyRender: false,
    shouldRerenderOnTransaction: false,
    extensions: [
      StarterKit.configure({ heading: { levels: [1, 2, 3] } }),
      Placeholder.configure({ placeholder: "Type / for commands..." }),
      TaskList,
      TaskItem.configure({ nested: true }),
      TextAlign.configure({ types: ["heading", "paragraph"] }),
      TextStyle,
      Color,
      Highlight.configure({ multicolor: true }),
      Table,
      ResizableImage,
      ImagePlaceholder,
      SlashCommand.configure({
        suggestion: getSlashCommandSuggestion([
          imagePlaceholderSlashCommandItem,
          tableSlashCommandItem,
        ]),
      }),
    ],
  });

  return (
    <div className="relative mx-auto w-full max-w-3xl px-4">
      <BlockEditor editor={editor} />
      <TableHoverOverlay editor={editor} />
    </div>
  );
}
```

The block editor fills its container, and its drag handles sit in a gutter on the left. Put it in a container with a max width and some side padding, such as `mx-auto w-full max-w-3xl px-4`, so the handles don't land on the edge of the window.

<Callout title="Next.js with cacheComponents">
  Tiptap's `useEditor` reads `Math.random()`, which Next.js `cacheComponents`
  rejects during prerender. If you get that error, render the editor inside a
  `<Suspense>` boundary.
</Callout>

## Full setup in one command

To start from the complete editors on the [homepage](/), with every control and all editorcn extensions (callout, code block, image placeholder, markdown, mention, paste cleanup, table and toggle) already wired up, install a full setup instead:

```bash
npx shadcn@latest add @editorcn/full-editor
npx shadcn@latest add @editorcn/full-block-editor
```

See [Full setup](/docs/editor#full-setup) for the toolbar editor and [Full setup](/docs/block-editor#full-setup) for the block editor.

> See the [@editorcn/editor docs](./editor) or [@editorcn/block-editor docs](./block-editor) for detailed API references.

## Peer dependencies

All `@tiptap/*` packages are **peer dependencies**, so your project has a single copy of Tiptap and its types don't clash.

The shadcn CLI installs every `@tiptap/*` package an item needs. With npm, the install commands above list them.

### Keep Tiptap versions in sync

Every `@tiptap/*` package requires the exact same version of the others. For example, `@tiptap/extension-mention@3.32.0` only works with `@tiptap/core@3.32.0`.

The shadcn CLI installs the newest Tiptap version in the range an item lists. If your project is on an older Tiptap release, that newer package won't match the ones you already have, and npm stops with an error like this:

```txt
npm error code ERESOLVE
npm error Conflicting peer dependency: @tiptap/pm@3.32.0
```

To fix it, upgrade all your `@tiptap/*` packages to the same version, then run the `shadcn add` command again:

```bash
npm install @tiptap/core@latest @tiptap/pm@latest @tiptap/react@latest @tiptap/starter-kit@latest
```

Include every `@tiptap/*` package listed in your `package.json`. If npm still reports a conflict, your lockfile is holding on to the old versions: delete `node_modules` and `package-lock.json` and run `npm install` again. With pnpm, run `pnpm up "@tiptap/*" --latest`.
