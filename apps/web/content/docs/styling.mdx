Both `@editorcn/editor` and `@editorcn/block-editor` are styled using **CSS custom properties** (design tokens) defined by your shadcn/ui theme. This means they automatically adapt to your existing design system — light mode, dark mode, brand colors, border radius, and fonts.

## How it works

The editors don't hardcode colors, spacing, or fonts. Everything comes from your theme variables like `--primary`, `--background`, `--border` and `--radius`, which your shadcn globals define:

```css
/* globals.css */
:root {
  --background: oklch(1 0 0);
  --foreground: oklch(0.2686 0 0);
  --primary: oklch(0.7686 0.1647 70.0804);
  --border: oklch(0.9276 0.0058 264.5313);
  --radius: 0.375rem;
  --font-mono: JetBrains Mono, monospace;
  /* ... */
}

.dark {
  --background: oklch(0.2046 0 0);
  --foreground: oklch(0.9219 0 0);
  --border: oklch(0.3715 0 0);
  /* ... */
}
```

They're used in three places:

- **Chrome**: the toolbar, bubble menus, dropdowns, popovers, slash menu and drag handle are styled with Tailwind classes such as `bg-popover`, `border-border` and `text-muted-foreground`, so Tailwind has to see the editor files. With the registry they're in your project. With npm, add the package to `@source` (see [Getting Started](/docs/getting-started)).
- **Content**: headings, lists, code, tables and the rest of the document come from a [content preset](#content-presets) in the editor's `style.css`, written in plain CSS with `var()`.
- **Animations**: menus and popovers animate with `animate-*` classes whose keyframes live in your Tailwind theme. The shadcn CLI adds them to your CSS when you install an item (see [Animations](#animations)).

## Dark mode

Both editors fully support dark mode. To enable it:

1. Set up `next-themes` with `attribute="class"`:

   ```tsx
   import { ThemeProvider } from "next-themes";

   function Providers({ children }) {
     return (
       <ThemeProvider attribute="class" defaultTheme="system" enableSystem>
         {children}
       </ThemeProvider>
     );
   }
   ```

2. The `.dark` class on `<html>` automatically switches the editor's colors.

No editor-specific configuration is needed — it just works.

## Customizing the theme globally

Override any CSS variable in your own stylesheet to change the editors' appearance:

```css
@import "@editorcn/editor/style.css";
@import "@editorcn/block-editor/style.css";

:root {
  --primary: oklch(0.6 0.2 250);
  --radius: 0.5rem;
  --font-mono: "Fira Code", monospace;
}

.dark {
  --background: oklch(0.15 0 0);
  --border: oklch(0.3 0 0);
}
```

### Available variables

| Variable                                | Affects                                                                   |
| --------------------------------------- | ------------------------------------------------------------------------- |
| `--background`, `--foreground`          | Editor and toolbar background, text, tooltips                             |
| `--primary`, `--primary-foreground`     | Links, checked task boxes, selected swatches, focus accents               |
| `--popover`, `--popover-foreground`     | Bubble menus, dropdowns, popovers, the slash menu                         |
| `--accent`, `--accent-foreground`       | Hovered and active controls and menu items                                |
| `--muted`, `--muted-foreground`         | Code and inline code backgrounds, hover backgrounds, placeholders, labels |
| `--secondary`, `--secondary-foreground` | Secondary buttons in dialogs and the image placeholder                    |
| `--border`, `--input`                   | Editor border, separators, blockquote line, inputs                        |
| `--ring`                                | Focus rings and the selected embed outline                                |
| `--destructive`                         | Delete actions and error messages                                         |
| `--radius`                              | Code blocks, images, embeds and other content corners                     |
| `--font-mono`                           | Code blocks and inline code                                               |

## Scoping overrides to a single editor

Wrap an editor in a container with a CSS class and scope your overrides:

```css
.my-custom-editor {
  --primary: oklch(0.7 0.25 150);
  --radius: 0.25rem;
}
```

```tsx
<div className="my-custom-editor">
  <RichTextEditor editor={editor}>
    <RichTextEditor.Toolbar>
      <RichTextEditor.Bold />
    </RichTextEditor.Toolbar>
    <RichTextEditor.Content />
  </RichTextEditor>
</div>
```

This keeps your global theme intact while giving a single editor a different look.

## Per-instance className

Every component accepts a `className` prop. It's merged with the default classes using `tailwind-merge`, so a Tailwind class you pass replaces the default it conflicts with. For example, `bg-muted/50` replaces the toolbar's background instead of fighting it.

### RichTextEditor

```tsx
<RichTextEditor editor={editor} className="rounded-lg shadow-md">
  <RichTextEditor.Toolbar className="bg-muted/50" />
  <RichTextEditor.Content className="min-h-[300px]" />
</RichTextEditor>
```

### BlockEditor

```tsx
<BlockEditor editor={editor} className="max-w-3xl mx-auto" />
```

## Content presets

The document styles come in two presets. Pick one with the `preset` prop:

| Preset       | Look                                                   | Default for                     |
| ------------ | ------------------------------------------------------ | ------------------------------- |
| `"document"` | Compact headings and spacing, styled task checkboxes   | `RichTextEditor`                |
| `"block"`    | Larger headings, roomier blocks, tables and task lists | `BlockEditor`, `StaticRenderer` |

```tsx
<RichTextEditor editor={editor} preset="block">
  ...
</RichTextEditor>

<StaticRenderer content={html} preset="document" />
```

Render saved content with the same preset it was written in, so `StaticRenderer` output matches the editor. The content element gets the `editorcn-content` class and a `data-preset` attribute, which the preset rules target:

```css
.editorcn-content[data-preset="document"] h1 {
  font-size: 1.75rem;
}
```

## Animations

Menus, popovers and the toolbar scroll fade use Tailwind theme animations. With the registry, the shadcn CLI adds these to the `@theme` block in your CSS. With npm, you import them with the package's `theme.css`.

| Variable                                 | Used by                                       |
| ---------------------------------------- | --------------------------------------------- |
| `--animate-rte-bubble-pop-in`            | Editor bubble menu, its dropdowns, embed menu |
| `--animate-rte-toolbar-fade`             | Editor toolbar edge fade on small screens     |
| `--animate-block-editor-bubble-pop-in`   | Block editor bubble menu and its dropdowns    |
| `--animate-block-editor-slide-in`        | Slash command menu                            |
| `--animate-block-editor-fade-in`, `-out` | Block editor touch toolbar edge fades         |
| `--animate-ext-pop-in`                   | Extension popovers and dropdowns              |
| `--animate-ext-tooltip-in`               | Extension tooltips                            |
| `--animate-ext-table-pop-in`             | Table row and column handles                  |

To change one, set it again in your own `@theme` block, after the editor's:

```css
@theme {
  --animate-rte-bubble-pop-in: rte-bubble-pop-in 120ms ease-out forwards;
}
```

`@editorcn/editor` shortens its animations and transitions to 1ms when the user has `prefers-reduced-motion` set.

## CSS class reference

Every editor element has a scoped class you can target from your own CSS.

- **Chrome classes** (toolbar, menus, buttons) carry Tailwind classes, which live in Tailwind's `utilities` cascade layer. Any plain CSS rule outside a layer wins over them, so no `!important` is needed.
- **Content selectors** (`.rte-content .ProseMirror p` and so on) have the same specificity as the preset rules, so the stylesheet loaded last wins. To win regardless of load order, start the selector with `.rte-root` or `.block-editor`, as the examples below do.

### @editorcn/editor

| Class                                               | What it styles                                                     |

| `.rte-root`                                         | Editor container, with `data-variant`                              |

| `button.rte-control-button`                         | Toolbar buttons                                                    |
| `.rte-editor-icon`                                  | Icons inside toolbar buttons                                       |
| `.rte-content`                                      | Content wrapper (also `.editorcn-content`)                         |
| `.rte-content .ProseMirror`                         | Content editing area                                               |
| `.rte-content .ProseMirror p`, `h1`–`h6`            | Paragraphs and headings                                            |
| `.rte-content .ProseMirror ul`, `ol`, `li`          | Lists                                                              |
| `.rte-content .ProseMirror blockquote`              | Blockquotes                                                        |
| `.rte-content .ProseMirror code`, `pre`             | Inline code and code blocks                                        |
| `.rte-content .ProseMirror hr`, `a`                 | Horizontal rules and links                                         |

## Common customizations

### Change icon size

Icons in the toolbar are rendered inside `.rte-editor-icon`. Override their size:

```css
.rte-editor-icon {
  width: 1.25rem;
  height: 1.25rem;
}
```

Or for a specific variant:

```css
/* Compact variant icons are already smaller */
.rte-root[data-variant="compact"] .rte-editor-icon {
  width: 0.875rem;
  height: 0.875rem;
}
```

### Change control button size

```css
/* All variants */
button.rte-control-button {
  width: 2.25rem;
  height: 2.25rem;
}

/* Only default variant */
.rte-root[data-variant="default"] .rte-controls-group > button {
  min-width: 2rem;
  height: 2rem;
}
```

### Change paragraph font size

```css
.rte-root .rte-content .ProseMirror p {
  font-size: 1.125rem;
  line-height: 1.8;
}
```

For the block editor:

```css
.block-editor .block-editor-content .ProseMirror p {
  font-size: 1.125rem;
  line-height: 1.8;
}
```

### Change heading sizes

```css
.rte-root .rte-content .ProseMirror h1 {
  font-size: 2rem;
}
.rte-root .rte-content .ProseMirror h2 {
  font-size: 1.5rem;
}
.rte-root .rte-content .ProseMirror h3 {
  font-size: 1.25rem;
}
```

### Change content area min-height

```css
.rte-root .rte-content .ProseMirror {
  min-height: 400px;
}
```

### Change toolbar button gap

```css
.rte-toolbar {
  gap: 0.5rem;
}
```

### Customize code blocks

```css
.rte-root .rte-content .ProseMirror pre {
  border-radius: 0.5rem;
  padding: 1.25rem;
  font-size: 0.8125rem;
}
```

### Customize link editor popover

```css
.rte-link-editor {
  gap: 0.5rem;
  padding: 0.5rem;
}

.rte-link-editor-input {
  min-width: 250px;
  padding: 0.375rem 0.5rem;
  border: 1px solid var(--border);
  border-radius: calc(var(--radius) - 2px);
}
```

### Customize task checkboxes

```css
.rte-root .rte-task-list input[type="checkbox"] {
  width: 20px;
  height: 20px;
  border-radius: 4px;
}
```

### Customize the bubble menu (block editor)

```css
.block-editor-bubble-menu {
  height: 2.5rem;
  padding: 0 0.5rem;
  box-shadow: 0 4px 20px rgba(0, 0, 0, 0.15);
}

.block-editor-bubble-btn {
  height: 2rem;
  padding: 0 0.5rem;
  font-size: 0.875rem;
}

.block-editor-bubble-btn svg {
  width: 1rem;
  height: 1rem;
}
```

### Customize the slash command menu

```css
.block-editor-slash-menu {
  max-height: 400px;
  min-width: 240px;
}

.block-editor-slash-menu-item {
  padding: 0.625rem 0.75rem;
}

.block-editor-slash-menu-item-label {
  font-size: 0.875rem;
}

.block-editor-slash-menu-item-desc {
  font-size: 0.8125rem;
}
```

### Change block editor heading sizes

```css
.block-editor .block-editor-content .ProseMirror h1 {
  font-size: 2rem;
}

.block-editor .block-editor-content .ProseMirror h2 {
  font-size: 1.625rem;
}

.block-editor .block-editor-content .ProseMirror h3 {
  font-size: 1.375rem;

```

### Customize drag handle

```css
.drag-handle {
  width: 1.5rem;
  height: 1.75rem;
  opacity: 1;
  color: var(--muted-foreground);
}

.drag-handle:hover {
  background: var(--accent);
  color: var(--accent-foreground);
}
```

## Variant-specific overrides

The editor uses `data-variant` attribute on the root element. Use it to target specific variants:

```css
/* Target subtle variant */
.rte-root[data-variant="subtle"] {
  box-shadow: 0 2px 6px rgba(0, 0, 0, 0.08);
}

/* Target compact variant */
.rte-root[data-variant="compact"] .rte-controls-group > button {
  min-width: 1.5rem;
  height: 1.5rem;
}
```

## Fonts

The editors use your page's font for text and `var(--font-mono)` for code. Set them in your `globals.css`:

```css
:root {
  --font-mono: JetBrains Mono, monospace;
}
```

Or pass a font class to the editor container:

```tsx
<RichTextEditor editor={editor} className="font-serif">
  ...
</RichTextEditor>
```

## Import order

Import the editor CSS **after** your shadcn globals so variables are defined:

```css
@import "./globals.css"; /* your shadcn theme variables */
@import "@editorcn/editor/style.css";
@import "@editorcn/block-editor/style.css";
```

With npm installs, also import each editor package's theme and add the package to Tailwind's sources, in the CSS file that imports `tailwindcss`, as described in [Getting Started](/docs/getting-started):

```css
@import "@editorcn/editor/theme.css";
@import "@editorcn/block-editor/theme.css";
@source "../node_modules/@editorcn/editor/dist";
@source "../node_modules/@editorcn/block-editor/dist";
```
