editorcn packages are available as a [shadcn registry](https://ui.shadcn.com/docs/registry), allowing you to install the source code directly into your project using the shadcn CLI. **This is the recommended way to install editorcn packages** — it copies the editor source straight into your project so you have full control over styling and behavior, rather than depending on a published `node_modules` package.

If you'd rather install from npm instead, see [npm vs registry](#npm-vs-registry) below for the tradeoffs.

## Setup

Add the editorcn registry to your `components.json`:

```json
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "registries": {
    "@editorcn": "https://www.rtecn.space/r/styles/{style}/{name}.json"
  }
}
```

This needs shadcn CLI 4.7.0 or newer (`npx shadcn@latest` always is). Older versions put the files in a literal `@components/` folder instead of your components directory.

The shadcn CLI fills in `{style}` from the `style` in your `components.json`, so you get the build for your base:

| Your `style`                         | You get             |
| ------------------------------------ | ------------------- |
| `base-*` (for example `base-nova`)   | Base UI components  |
| `radix-*` (for example `radix-nova`) | Radix UI components |
| `new-york`, `default`                | Radix UI components |
| `aria-*`                             | Not supported yet   |

<Callout title="Check your iconLibrary">
  The icons are written for the `iconLibrary` in your `components.json`, which
  must be `lucide`, `tabler`, `hugeicons`, `phosphor` or `remixicon`. Older
  projects with `"iconLibrary": "radix"` get a build error about
  `./icon-placeholder`. Change it to `"lucide"` before installing, and install
  `lucide-react` if your project doesn't have it (the CLI doesn't install icon
  packages). See [Icon library](/docs/editor#icon-library).
</Callout>

Only a few of the editor's own primitives depend on the base (button, dialog, input, popover, toggle and tooltip), and they look the same in every style, so `base-vega` and `base-nova` get the same editorcn files. shadcn components that the templates use, like `dropdown-menu`, still come from your own style.

<Callout>
  React Aria styles (`aria-*`) aren't supported yet. The CLI asks for
  `/r/styles/aria-nova/...`, which doesn't exist, and the install fails with a
  404. Use a `base-*` or `radix-*` style for now.
</Callout>

### Installing by URL

You can also install an item by its full URL without adding the registry. Pick the base in the URL:

```bash
npx shadcn@latest add "https://www.rtecn.space/r/styles/radix-nova/editor.json"
```

Install commands in these docs show a base switch next to the package manager tabs, so you can copy the URL for your base. The older URLs without `/styles/` (`https://www.rtecn.space/r/editor.json`) still work and always install the Base UI build.

## Usage

After installation, the editor source files are in your project at `components/editor/` (or `components/block-editor/` for the block editor).

### 1. Import styles

Import the editor styles alongside your shadcn globals:

```tsx
// Your shadcn globals
import "@/app/globals.css";

// Editor component styles
import "@/components/editor/style.css";
```

For the block editor:

```tsx
import "@/components/block-editor/style.css";
```

### 2. Install peer dependencies

The `@tiptap/*` packages are peer dependencies. The shadcn CLI will prompt you to install any it detects as missing, but you can also add them yourself:

```bash
npm install @tiptap/react @tiptap/pm @tiptap/starter-kit @tiptap/extension-link @tiptap/extension-underline
```

See the [Editor](./editor) or [Block Editor](./block-editor) docs for the full list of extensions.

All `@tiptap/*` packages must be on the same version. If an install fails with `ERESOLVE`, see [Keep Tiptap versions in sync](./getting-started#keep-tiptap-versions-in-sync).

### 3. Use the components

**Rich text editor:**

```tsx
"use client";

import { useEditor } from "@tiptap/react";
import { StarterKit } from "@tiptap/starter-kit";
import { Placeholder } from "@tiptap/extension-placeholder";
import { RichTextEditor, Link } from "@/components/editor";

function MyEditor() {
  const editor = useEditor({
    immediatelyRender: false,
    extensions: [
      StarterKit,
      Link,
      Placeholder.configure({ placeholder: "Start typing..." }),
    ],
  });

  return (
    <RichTextEditor editor={editor}>
      <RichTextEditor.Toolbar sticky>
        <RichTextEditor.ControlsGroup>
          <RichTextEditor.Bold />
          <RichTextEditor.Italic />
          <RichTextEditor.Underline />
        </RichTextEditor.ControlsGroup>
      </RichTextEditor.Toolbar>
      <RichTextEditor.Content />
    </RichTextEditor>
  );
}
```

**Block editor:**

```tsx
"use client";

import { useEditor } from "@tiptap/react";
import { StarterKit } from "@tiptap/starter-kit";
import { Placeholder } from "@tiptap/extension-placeholder";
import {
  BlockEditor,
  SlashCommand,
  defaultSlashCommandItems,
  getSlashCommandSuggestion,
} from "@/components/block-editor";

function MyBlockEditor() {
  const editor = useEditor({
    immediatelyRender: false,
    extensions: [
      StarterKit.configure({ heading: { levels: [1, 2, 3] } }),
      Placeholder.configure({ placeholder: "Type / for commands..." }),
      SlashCommand.configure({
        suggestion: getSlashCommandSuggestion(defaultSlashCommandItems),
      }),
    ],
  });

  return <BlockEditor editor={editor} />;
}
```

For the full API reference, props, and customization options, see the [Editor](./editor) and [Block Editor](./block-editor) pages.

## How it works

The registry is served as static JSON files, one folder per base:

- **`/r/styles/base-nova/`**: every item built with Base UI primitives
- **`/r/styles/radix-nova/`**: the same items built with Radix UI primitives
- **`/r/styles/index.json`**: the list of bases
- **`/r/{name}.json`**: the Base UI build at the older URLs, for existing installs

Each folder has a `registry.json` catalog and one JSON file per item. Other `base-*` and `radix-*` style names are served from these two folders.

When you run `shadcn add @editorcn/editor` in a project with `"style": "radix-nova"`, the CLI:

1. Fetches `https://www.rtecn.space/r/styles/radix-nova/editor.json`
2. Reads the `files` array to know which source files to install
3. Copies each file's `content` into your project at the configured paths
4. Installs all `dependencies` into your project

## npm vs registry

|                          | npm                                 | Registry (recommended)                 |
| ------------------------ | ----------------------------------- | -------------------------------------- |
| Install location         | `node_modules`                      | Your project source                    |
| Customizable             | No (published dist)                 | Yes (edit the source)                  |
| Versioning               | Semver via npm                      | Latest from source                     |
| Peer dependency handling | Manual install                      | CLI prompts for missing ones           |
| Use case                 | Quick setup, no source edits needed | Full control over styling and behavior |

Use the registry unless you have a specific reason to prefer a versioned npm dependency (for example, pinning to an exact release in a monorepo with strict dependency management).
